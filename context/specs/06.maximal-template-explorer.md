# Spec 06 — Maintain the Tenant Application Explorer

**Priority:** P6  
**Depends on:** Spec 05

## Issue intent

Keep the breadth of the Maximal Template discoverable inside the authenticated tenant application.

The old requirement for signed-out access to tenant recipe areas is superseded.

## Admission

Tenant navigation is available after:

```text
authentication
→ onboarding completion
→ tenant shell
```

The public landing/auth surfaces provide the entrance to the application.

## Tenant navigation scope

The tenant shell currently exposes or supports major application areas including:

- Dashboard;
- CRM;
- Projects;
- Support;
- Marketing;
- Invoices;
- Expenses;
- Social;
- AI;
- Portal;
- Admin;
- Settings;
- My Tasks.

Navigation should reflect routes that actually exist.

Do not add `/invoicing`, `/user`, or another abstract segment solely because a governance vocabulary contains that term.

## Shell responsibility

`components/shells/tenant-shell.tsx` owns tenant shell composition and navigation behavior.

Navigation/shell code must not become a replacement for:

- persisted domain data access;
- authorization policy;
- provider SDK orchestration;
- business workflows.

Dynamic data should enter through the existing application boundaries.

## Responsive behavior

Preserve current responsive/keyboard behavior.

Mobile navigation must remain operable and must restore focus appropriately when dismissed.

## Explorer/status surfaces

Where the existing application includes component, integration, architecture, or status surfaces, preserve their role as application-inspection aids.

Do not expose secrets or claim provider availability without evidence.

## Acceptance criteria

- [ ] Tenant navigation remains behind authentication and onboarding.
- [ ] Major implemented application areas remain discoverable.
- [ ] Navigation targets real current routes.
- [ ] Admin targets the real `/admin` segment.
- [ ] Invoicing navigation respects `/invoices` and `/expenses`.
- [ ] Shell/navigation code remains presentation-oriented.
- [ ] Responsive keyboard behavior is preserved.
- [ ] Provider/status surfaces do not expose secrets or fake configuration.
